# ビジネスルール — Unit 1: LINE Bot基盤

**作成日**: 2026-05-16  
**Unit**: Unit 1 — LINE Bot基盤  
**対応要件**: F1-01, F1-02, F1-03, F1-04, SEC-01

---

## BR-1: 署名検証ルール

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-1-01 |
| **対応要件** | F1-01, SEC-01 |
| **説明** | すべての Webhook リクエストは `X-Line-Signature` ヘッダーによる HMAC-SHA256 署名検証を **必須** とする |
| **検証方法** | `line_service.verify_signature(body, signature)` |
| **失敗時** | HTTP 403 を返却。ボディ処理は一切行わない |
| **ログ** | 署名検証失敗は `logger.warning()` で記録（リクエスト内容はログに含めない） |

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-1-02 |
| **対応要件** | SEC-01 |
| **説明** | `X-Line-Signature` ヘッダーが存在しない場合は署名検証失敗と同等に扱う |
| **失敗時** | HTTP 403 を返却 |

## BR-2: ウォームアップルール

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-2-01 |
| **対応要件** | F1-04 |
| **説明** | `event.get("source") == "warmup"` の場合、署名検証をスキップして即座に `{"statusCode": 200}` を返却する |
| **優先順位** | 処理フローの最初（署名検証よりも前）に判定する |
| **目的** | Lambda のコールドスタート削減（EventBridge Scheduler による定期ウォームアップ） |

## BR-3: メッセージルーティングルール

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-3-01 |
| **対応要件** | F1-02 |
| **説明** | `event.type == "message"` の場合のみメッセージルーティングを実行する |
| **その他イベント** | `follow`, `unfollow`, その他は Unit 1 では無視（200 返却、ログ出力のみ） |

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-3-02 |
| **対応要件** | F1-02 |
| **説明** | `message.type` による分岐ルール |
| **text** | ルーティング対象（Unit 1: エコー応答 / Unit 2 以降: Intent 分類） |
| **image** | ルーティング対象（Unit 1: 固定応答 / Unit 3 以降: レシート解析） |
| **その他** | 未対応応答（BR-4 適用） |

## BR-4: 未対応メッセージ応答ルール

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-4-01 |
| **対応要件** | F1-03 |
| **説明** | `sticker`, `video`, `audio`, `file`, `location` メッセージに対しては `UNSUPPORTED_REPLIES` リストからランダムに 1 つ選択して Reply する |
| **Bedrock 呼び出し** | 不要（固定テンプレートのみ） |
| **選択方法** | `random.choice(UNSUPPORTED_REPLIES)` |

**UNSUPPORTED_REPLIES**:
1. `"スタンプかわいい〜！でもリワードちゃん、文字の方が得意なんだ😊"`
2. `"ん〜それはまだ読めないかも！テキストで話しかけてくれると嬉しいな〜"`
3. `"おっ、それ気になる！…けど今はテキストだけ対応してるんだ〜ごめんね🥲"`

## BR-5: エラーフォールバックルール

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-5-01 |
| **対応要件** | F1-03 |
| **説明** | メッセージ処理中に未捕捉例外が発生した場合、リワードちゃん口調の固定エラーメッセージを Reply する |
| **エラー文言** | `"ちょっと調子が悪いみたい…またあとで話しかけてね🥲"` |
| **ログ** | `logger.exception()` でスタックトレースを記録（PII マスク適用） |

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-5-02 |
| **対応要件** | F1-03 |
| **説明** | エラーフォールバックの Reply 送信自体が失敗した場合は、ログ出力のみで二重障害を防ぐ |
| **理由** | Reply Token が既に使用済み or 期限切れの場合がある |

## BR-6: HTTP レスポンスルール

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-6-01 |
| **説明** | LINE Platform に対しては常に HTTP 200 を返却する（署名検証失敗時の 403 を除く） |
| **理由** | LINE Platform は 200 以外を受け取ると Webhook リトライを行い、重複処理の原因となる |

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-6-02 |
| **説明** | イベント処理中の例外は catch して 200 を返却する。Lambda 自体のエラー（500）にはしない |
| **理由** | BR-6-01 と同じ。処理失敗でも LINE Platform へは 200 を返す |

## BR-7: PII 保護ルール

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-7-01 |
| **対応要件** | SEC-01 |
| **説明** | `source.userId`（LINE ユーザー ID）はログに出力しない。`PIIMaskingLogger` を使用する |
| **対象** | すべてのログ出力で `line_user_id` フィールドが自動マスクされる |

| 項目 | 内容 |
|------|------|
| **ルール ID** | BR-7-02 |
| **対応要件** | SEC-01 |
| **説明** | `message.text`（ユーザーのメッセージ本文）はログに出力しない |
| **対象** | `PIIMaskingLogger` により `message` フィールドが自動マスクされる |
