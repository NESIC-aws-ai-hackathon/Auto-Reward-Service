# Unit 6 Push 通知（リワードちゃんからの連絡）

## 設計思想

> **「友達がふと LINE してくる感じ」を再現する。**
>
> リワードちゃんは Bot ではなく「お金のことをちょっと知ってる友達」。
> 1日のどこかで、ふとスマホに通知が来る。開いたらリワードちゃん。
> いつ来るかわからないから、本物の友達みたい。
>
> **全メッセージのルール：**
> ❌ 「ねーねー！」「やっほ〜」だけ → 何を返していいかわからない。うざい彼女感
> ✅ 具体的な話題 + 答えやすい問いかけ → つい返したくなる友達感
>
> **全テンプレートは以下の構造：**
> 1. 具体的な話題（商品名、過去の記録、選択肢など）
> 2. 答えやすい問いかけ（Yes/No、2択、短い回答）
> 3. 可能な限りユーザーのデータに接続（過去の支出、嗜好、残予算）

---

## 1. Push 通知の種類

| # | 種類 | 頻度 | 時間帯 | 優先度 |
|---|---|---|---|---|
| 1 | **リワードちゃんからの連絡** | 毎日1回 | **10:00〜21:00（ランダム）** | **P0** |
| 2 | **月初レポート** | 月1回（1日） | 9:00 | **P0** |
| 3 | **記念日リマインダー** | 7日前・当日 | 10:00〜21:00 | **P1** |
| 4 | **オンボーディング完了通知** | 初回1回 | 即時 | P0（LIFF側で処理済み） |

### ハッカソン Push 通数

```
審査員 5人 × 毎日1通 × 30日 = 150通
月初+記念日: ~10通
合計: ~160通/月 → フリープラン 200通以内 ✅
```

```python
def _get_tone(hour: int) -> str:
    if 10 <= hour < 12:
        return random.choice(["ねね、", "そういえばさ、", "ちょっと聞きたいんだけど、"])
    elif 12 <= hour < 14:
        return random.choice(["お昼だ！", "ランチ中？", "ごはん食べた？"])
    elif 14 <= hour < 17:
        return random.choice(["ちょっと聞いてよ〜", "ひまな時でいいんだけど、", "急にごめんね笑"])
    elif 17 <= hour < 19:
        return random.choice(["おつかれ！", "仕事終わった？", "もう帰り？"])
    else:  # 19-21
        return random.choice(["夜だけどさ、", "寝る前にちょっと！", "今日もおつかれ〜！"])
```

## 3. 嗜好データの蓄積フロー

### 3.1 会話 → PREF_MEMORY 自動抽出

```
リワードちゃん Push:
  「突然だけどラーメンは何系が好き？🍜」
  ↓
ユーザー返信:
  「豚骨！一蘭よく行くよ」
  ↓
webhook_handler → character_reply（通常の会話処理）
  + preference_extractor.extract()
  ↓
Bedrock で抽出:
  {
    "category": "food",
    "items": ["豚骨ラーメン", "一蘭"],
    "context": "よく行く"
  }
  ↓
DynamoDB 更新:
  PREF_MEMORY#food: likes に「豚骨ラーメン」「一蘭」を追加
  ↓
リワードちゃん Reply:
  「一蘭いいよね〜！✨
   そしたら今度豚骨系の新しいお店見つけたら教えるね🍜」
```

### 3.2 preference_extractor.py

```python
# layer/python/services/preference_extractor.py

EXTRACTION_PROMPT = """
以下のユーザー発言から嗜好情報を JSON で抽出してください。

会話文脈: リワードちゃんが「{context_question}」と質問した
ユーザー回答: "{user_message}"

出力形式:
{{
  "category": "food" | "entertainment" | "hobby" | "lifestyle" | "fashion" | "place" | "brand" | "other",
  "items": ["具体的な好み1", "好み2"],
  "sentiment": "positive" | "negative" | "neutral",
  "context": "補足情報（よく行く、最近ハマってる、など）"
}}

嗜好情報が含まれない場合:
{{"category": null, "items": [], "sentiment": "neutral", "context": null}}

JSON のみ出力:
"""


def extract_preferences(context_question: str, user_message: str) -> dict:
    result = bedrock_service.invoke_text(
        EXTRACTION_PROMPT.format(
            context_question=context_question,
            user_message=user_message
        )
    )
    return json.loads(result)


def save_preferences(user_id: str, extracted: dict):
    if not extracted.get("items"):
        return

    category = extracted["category"]
    items = extracted["items"]

    # 既存の嗜好データを取得
    existing = dynamodb_service.get_preference(user_id, category)
    existing_likes = existing.get("likes", [])

    # 重複排除して追加
    for item in items:
        if item not in existing_likes:
            existing_likes.append(item)

    dynamodb_service.put_preference(user_id, category, {
        "likes": existing_likes,
        "last_updated": datetime.now().isoformat(),
        "last_context": extracted.get("context"),
    })
```

## 4. メッセージ生成ロジック

```python
def generate_daily_push(user_id: str) -> Optional[dict]:

    # 1. Push 設定チェック
    settings = dynamodb_service.get_push_settings(user_id)
    if not settings.get("all_enabled", True):
        return None
    if not settings.get("daily_message", True):
        return None

    # 2. ユーザー情報を取得
    profile = dynamodb_service.get_profile(user_id)
    prefs = dynamodb_service.get_all_preferences(user_id)
    budget = finance_engine.get_monthly_remaining(user_id)
    streak = dynamodb_service.get_streak(user_id)
    recent_expenses = dynamodb_service.get_recent_expenses(user_id, days=14)
    anniversaries = dynamodb_service.get_upcoming_anniversaries(user_id, days=7)

    # 3. 記念日が近い場合は優先
    if anniversaries and settings.get("anniversary", True):
        return _build_anniversary_message(profile, anniversaries[0], budget)

    # 4. 嗜好データの充実度で deep_dive の重みを調整
    pref_count = sum(len(p.get("likes", [])) for p in prefs.values())
    if pref_count < 5:
        # まだ嗜好データが少ない → deep_dive の重みを上げる
        DAILY_CATEGORIES["deep_dive_preference"]["weight"] = 5
    else:
        # 嗜好データが充実 → おすすめの精度が上がるので recommendation の重みを上げる
        DAILY_CATEGORIES["specific_recommendation"]["weight"] = 5
        DAILY_CATEGORIES["deep_dive_preference"]["weight"] = 1

    # 5. 過去の記録がある場合は past_reference を有効化
    if not recent_expenses:
        DAILY_CATEGORIES["past_reference"]["weight"] = 0

    # 6. 有効なカテゴリだけでランダム選択
    enabled_categories = {
        k: v for k, v in DAILY_CATEGORIES.items()
        if v["weight"] > 0 and settings.get(_category_to_setting_key(k), True)
    }

    category = _weighted_random_choice(enabled_categories)

    # 7. 時間帯トーン
    tone = _get_tone(datetime.now().hour)

    # 8. テンプレ選択 + 変数埋め
    template = random.choice(enabled_categories[category]["templates"])
    message = _fill_template(template, tone, profile, prefs, budget, streak, recent_expenses)

    # 9. 送信記録（どのカテゴリで送ったか記録。同じ質問を繰り返さない用）
    dynamodb_service.log_push(user_id, category, template)

    return {"type": "text", "text": message}
```

## 5. ランダム配信アーキテクチャ（10:00〜21:00）

```
10:00 EventBridge → PushSchedulerFunction
  ├── 全ユーザーを取得
  ├── 各ユーザーの PUSH_SETTINGS を確認
  ├── 10:00〜21:00 のランダム時刻を計算
  └── PUSH_QUEUE#{date} に書き込み

10分おき EventBridge → PushDispatcherFunction
  ├── PUSH_QUEUE から scheduled_at <= now AND status=pending を取得
  ├── daily_push.generate_daily_push() でメッセージ生成
  ├── line_service.push_message() で送信
  └── status を "sent" に更新、PUSH_LOG に記録
```

## 10. 実装優先度

| 優先度 | 機能 | 理由 |
|---|---|---|
| **P0** | PushScheduler + PushDispatcher | 「いつ来るかわからない」友達感の根幹 |
| **P0** | 全テンプレート（具体的話題 + 質問形式） | 「返したくなる」がないと意味がない |
| **P0** | 月初レポート Push | 繰り越し機能のデモに必須 |
| **P0** | preference_extractor（嗜好自動抽出） | 会話→蓄積→提案 のサイクルの起点 |
| **P1** | 嗜好データ活用の個人化 Push | データが溜まるほど「わかってる感」増加 |
| **P1** | 記念日リマインダー | オンボーディングで登録後 |
| **P1** | LIFF 通知設定画面 | ユーザー体験の完成度 |
| **P1** | チャットから設定変更 | 「静かにして」で即変更 |
| **P2** | Push 通数管理 + 上限チェック | 本番化向け |
| **P2** | push_log で同じ質問の重複回避 | UX向上。ハッカソンでは後回し可 |
