# 要件定義書 — オートリワードサービス（確定版）

## 概要

| 項目 | 内容 |
|------|------|

---

## 1. プロジェクト概要

### エレベーターピッチ

> ストレスを感じた瞬間、財務状況を自動分析してユーザーに最適なご褒美を提案する AI サービス。
> 「買っていいよ」の一言を、自分の代わりに AI が言ってくれる。

### ビジョン

2027 年までに、日本国内の勤労世代（25〜45 歳）に月 1 回以上の「AI 承認ご褒美体験」を提供する家計管理プラットフォームになる。

## 2. 技術スタック（確定）

| レイヤー | 技術 | 備考 |
|----------|------|------|
| **フロントエンド** | React（TypeScript） | Web アプリのみ（MVP）。モバイル対応は後フェーズ |

## 3. アーキテクチャ方針

### MVP フェーズ（同期処理）

- マイクロサービス構成は維持しつつ、サービス間通信は **HTTP（REST）** で同期呼び出し
- Kafka / メッセージブローカーは **使用しない**（Growth フェーズで導入）
- すべてのサービスを **Docker Compose** で起動できるようにする
- サービス構成は要件定義書の Unit 構成に対応

### Growth フェーズ移行時の拡張ポイント

- サービス間通信を HTTP → Kafka イベントに段階移行できるよう、ドメインイベントインターフェースを抽象化して設計する
- モバイルアプリ（React Native）対応を後から追加できるよう API を RESTful に設計

## 6. 非機能要件

### 6.1 パフォーマンス

| 指標 | 目標値 |
|------|--------|
| 主要 API レスポンスタイム | p95 < 500ms |
| ストレス閾値超過 → 通知送信 | 60 秒以内（US-08 より） |
| フロントエンド初期ロード | LCP < 2.5s（Core Web Vitals） |

### 6.2 セキュリティ（Security Baseline 拡張：**有効**）

> セキュリティ拡張ルール（SECURITY-01〜）はすべての実装段階で必須制約として適用されます。

| 要件 | 詳細 |
|------|------|
| 認証・認可 | Auth0 / AWS Cognito による JWT 認証（全 API に適用） |
| 通信暗号化 | TLS 1.2+ 必須（SECURITY-01） |
| 保存データ暗号化 | DB / キャッシュの暗号化（SECURITY-01） |
| アクセスログ | API Gateway・ロードバランサーへのアクセスログ必須（SECURITY-02） |
| アプリログ | 構造化ログ、PII・トークンのログ出力禁止（SECURITY-03） |
| 月次予算上限 | 過剰消費防止のための支出警告機能を必須実装 |
| データ最小化 | サーバーへの送信データを最小化・端末内処理優先 |

### 6.3 テスト戦略（PBT 拡張：**Partial 適用**）

| テストレベル | 対象 |
|------------|------|
| ユニットテスト | 全サービスのビジネスロジック層 |
| 統合テスト | サービス間 HTTP 通信、DB 操作 |
| プロパティベーステスト（PBT） | 純粋関数・シリアライズのみ適用（Partial モード） |

> PBT 対象候補：ストレススコア算出ロジック、余裕額算出ロジック、リワード提案マトリクス変換

### 6.4 可観測性

- 構造化ログ（JSON 形式、correlation ID 付き）
- ヘルスチェックエンドポイント（`/health`）を全サービスに実装

### 6.5 スケーラビリティ

- 各サービスはステートレス設計（水平スケール可能）
- Growth フェーズで Kafka を導入できるよう、ドメインイベントインターフェースを分離して設計

## 7. API 設計（概要）

- **ベース URL**: `http://localhost:3000/api/v1`（ローカル）/ `https://api.auto-reward.app/v1`（本番）
- **認証**: Bearer JWT（Auth0 / Cognito 発行）、`/auth` 系エンドポイントを除く全 API に必須
- **レスポンス形式**: `application/json`
- **エラー形式**: `{ "error": { "code": "...", "message": "..." } }`

主要エンドポイントは `要件定義書.md` §12 参照。
