## 1. プロジェクト概要

### コンセプト

> **話すだけで家計簿になる。
> 好きなものを覚えて、買っていい理由をくれる。
> 頑張りすぎない家計簿アプリ「ARS」。**

ARSは「家計簿をつけようと頑張らない」ことが前提のサービス。
LINEでリワードちゃんと話すだけで、支出・感情ログ・嗜好・ご褒美履歴が **会話の副産物として** 育っていく。

### エレベーターピッチ

> LINEでリワードちゃんと話しているだけで、愚痴・支出・好み・ご褒美履歴が勝手に記録される。
> ユーザーは家計簿を頑張らない。でも気づいたら、自分の消費傾向が整理されている。
> そしてリワードちゃんは、ユーザーの好きなものや今月の余裕を覚えて、
> ちょうど弱っているタイミングで「これ買っちゃおうよ〜」と財布をゆるめてくる。

## 2. 技術スタック（確定）

| レイヤー | 技術 | 備考 |
|----------|------|------|
| **メッセージングUI** | LINE Messaging API（フリープラン） | 通常会話はReply中心、Push通知はデモ用・1日1回上限 |
| **LIFF** | LINE LIFF（最小限） | ご褒美メモ・履歴・設定・候補一覧のみ |
| **API エントリポイント** | Amazon API Gateway | LINE Webhookエンドポイント等 |
| **バックエンド** | AWS Lambda（Python） | 全関数をPythonで統一 |
| **データベース** | Amazon DynamoDB（シングルテーブルデザイン） | PK=`USER#{lineUserId}`、SK=エンティティ種別プレフィックス |
| **LLM** | Amazon Bedrock（Nova Micro / Nova Lite） | モデル切り替え可能設計。品質不足時は Claude Haiku/Sonnet |
| **画像解析** | Amazon Nova Lite（Bedrock）第一候補 | 精度不足時は Amazon Textract + LLM、または Claude Vision |
| **外部API** | 楽天ウェブサービスAPI | ご褒美候補プールの商品データ取得 |
| **認証** | LINEユーザーID（LINE Webhook署名検証） | LIFF利用時はLINEログインアクセストークンも取得 |
| **IaC** | AWS SAM（Serverless Application Model） | Lambda + API Gateway をコードで定義 |
| **セキュリティ重点** | LINE Webhook署名検証 + チャネルシークレット管理 | OWASP Top10 準拠も適用 |

## 3. アーキテクチャ方針

### システム構成

```
LINE ユーザー
  ↓（LINEアプリ）
LINE Messaging API
  ↓（Webhook）
Amazon API Gateway
  ↓
AWS Lambda（Python）
  ├ Message Router（Intent分類）
  ├ Intent Classifier（Nova Micro）
  ├ Expense Extractor（Nova Micro）
  ├ Receipt Image Analyzer（Nova Lite）
  ├ Yuru Finance Engine（余裕額算出）
  ├ Reward Pool Selector（候補プール選択）
  ├ Character Reply Generator（Nova Micro / Haiku）
  └ DynamoDB（シングルテーブル）

日次バッチ（EventBridge Scheduler）
  └ Reward Pool Updater Lambda
      ├ 楽天APIから商品取得
      └ DynamoDB reward_pool 更新

LIFF（最小限）
  ├ ご褒美メモ
  ├ 履歴
  ├ 設定
  └ 候補一覧
```

### データ構造（DynamoDBシングルテーブル）

| PK | SK | 内容 |
|----|----|------|
| `USER#{lineUserId}` | `PROFILE#` | ユーザープロフィール・収入・固定費 |
| `USER#{lineUserId}` | `FIXED_COSTS#` | 固定費一覧 |
| `USER#{lineUserId}` | `CHAT#{timestamp}` | チャットログ |
| `USER#{lineUserId}` | `LIFELOG#{timestamp}` | 感情・状態ログ |
| `USER#{lineUserId}` | `PENDING_EXPENSE#` | 確認待ち支出 |
| `USER#{lineUserId}` | `EXPENSE#{timestamp}` | 確定支出 |
| `USER#{lineUserId}` | `PREF_MEMORY#` | 嗜好・好み記憶 |
| `USER#{lineUserId}` | `REWARD_POOL#` | ご褒美候補プール |
| `USER#{lineUserId}` | `REWARD_SUGGESTION#{timestamp}` | 提案履歴 |

## 4. 機能要件（MVPスコープ）

> **除外機能**: アフィリエイト実装・サービス強度測定基盤

### F1: LINE Bot基盤

| 機能ID | 機能名 | 優先度 | 説明 |
|--------|--------|--------|------|
| F1-01 | Webhook受信・署名検証 | Must | LINE Webhookの受信とX-Line-Signature検証 |
| F1-02 | Message Router | Must | テキスト・画像・スタンプ等のルーティング |
| F1-03 | Reply / Push 送信 | Must | Reply API中心、Push APIはデモ用・1日1回上限管理 |
| F1-04 | Flex Message | Should | リッチな提案表示（Flex Messageカード） |

### F2: 初回登録フロー（チャット式）

| 機能ID | 機能名 | 優先度 | 説明 |
|--------|--------|--------|------|
| F2-01 | 新規ユーザー検出 | Must | 初回メッセージでユーザー登録トリガー |
| F2-02 | 収入ざっくり登録 | Must | リワードちゃんがチャットで月収・ボーナスを聞く |
| F2-03 | 固定費ざっくり登録 | Must | 家賃・通信費・サブスク等をチャットで聞く |
| F2-04 | ご褒美枠自動計算 | Must | 登録情報から初期ご褒美枠を自動提案 |

### F3: リワードちゃんキャラクター

| 機能ID | 機能名 | 優先度 | 説明 |
|--------|--------|--------|------|
| F3-01 | キャラ口調生成 | Must | Nova Micro でリワードちゃん口調のReply生成 |
| F3-02 | 口調カスタマイズ（2〜3種類） | Should | フレンドリー（デフォルト）+ やさしい敬語 + 小悪魔 |
| F3-03 | 制限到達時の退場演出 | Should | 「今日はいっぱい話したね〜。リワードちゃん寝るね」等 複数パターン |
| F3-04 | 感情・疲労度の間接把握 | Must | 「今日どうだった？」的な間接質問 + 発話テキストからLLMが感情推定 |

### F4: 支出記録（チャット + 画像）

| 機能ID | 機能名 | 優先度 | 説明 |
|--------|--------|--------|------|
| F4-01 | チャット支出入力 | Must | 「セブンでプリン買った」→ JSON化してDynamoDB保存 |

| F4-05 | ARSカテゴリ分類 | Should | 「食費」でなく「情緒安定費」「回復費」等のARS独自カテゴリ |

### F6: ご褒美提案

## 5. 非機能要件

### 5.1 セキュリティ（Security Baseline）

| 要件 | 内容 |
|------|------|
| SEC-01 | LINE Webhook リクエストの `X-Line-Signature` ヘッダー検証（必須） |
| SEC-02 | チャネルシークレット・アクセストークンは AWS Secrets Manager または SSM Parameter Store で管理（平文ハードコード禁止） |
| SEC-03 | DynamoDB 保存データの暗号化（AWS管理キー以上） |
| SEC-04 | ログに LINE ユーザーID・チャット内容等 PII を出力しない |
| SEC-05 | LIFF のオリジン検証（LINEのOAuthフロー遵守） |
| SEC-06 | Lambda 関数の IAM 権限は最小権限原則 |
| SEC-07 | API Gateway に AWS WAF の基本ルール適用（OWASP Top10対策） |

### 5.2 パフォーマンス

| 要件 | 内容 |
|------|------|
| PERF-01 | LINE Reply は Webhook受信から **3秒以内**（LINEの応答タイムアウト制約） |
| PERF-02 | レシート画像解析が1分超える場合は処理を非同期化し「結果を見る」ボタンで返す |
| PERF-03 | Lambda Cold Start 対策：Provisioned Concurrency または Lambdaウォームアップ方式 |

### 5.3 コスト

| 要件 | 内容 |
|------|------|
| COST-01 | 通常会話: 1ユーザー1日50〜100会話まで Nova Micro使用 |
| COST-02 | 画像解析: 標準5枚/日、上位ユーザー20枚/日 |
| COST-03 | Push通知: 月200通以内（LINEフリープラン上限遵守） |
| COST-04 | 制限到達時はキャラの退場演出（テンプレ返信ではなくキャラの都合で自然に閉じる） |

### 5.4 テスト戦略

| 要件 | 内容 |
|------|------|
| TEST-01 | LLM応答テスト重点：プロンプトに対する出力品質テスト |
| TEST-02 | Lambda関数のユニットテスト（pytest） |
| TEST-03 | Webhook受信〜DynamoDB保存の統合テスト |
| TEST-04 | 楽天API連携のモックテスト |
| TEST-05 | LINE署名検証ロジックのセキュリティテスト |

              プリンってなんてプリン？次に似たやつ見つけたい〜
ユーザー: 320円の濃厚たまごプリン
リワードちゃん: 濃厚たまごプリン、320円ね。覚えた〜。たまご系プリン、次も見張っとく。

## 1. プロジェクト概要
